# 实机与协议

验证日期：2026-10-13。上游 https://github.com/tsl0922/EPD-nRF5 ，研究提交 `7e3196193997bd6a4644610c41d54a76eff88760`。

- 设备名：`NRF_EPD_A571`。
- 固件字符串：`v1.10-nrf52811`。与所研究上游版本字段格式不同，实机包含 slots 等扩展；不要靠版本号推测支持能力。
- 配置 model_id=3，按上游映射为 UC8176、4.2 寸、400×300、黑白红。实机配置 14 字节，比上游 13 字节多一字节，含义未确认。
- 唤醒引脚为 0xFF；按所研究上游逻辑，广播超时后重新广播。不是所有型号都如此。
- EPD 服务：`62750001-d828-918d-fb46-b6c11c675aec`。
- 读写/通知特征：`62750002-d828-918d-fb46-b6c11c675aec`。
- 版本特征：`62750003-d828-918d-fb46-b6c11c675aec`。
- 订阅通知后第一条为配置；INIT `01` 返回 `mtu=244 rle=1` 等能力。不要记录或展示用途不明的 sid 通知。

图片转换为两个 15000 字节位平面，逐行、每字节高位在左。位值 0 表示该平面着色，1 表示不着色。上传脚本将红像素从黑平面排除。

命令：`01` 初始化当前型号；`30 flags data...` 写图片；`05` 刷新。不要在 INIT 后附加其他型号。

当设备通知 `rle=1` 时，flags bit0 选择黑(0)/红(1)，bit1 是平面首块，bit2 是 RLE 编码。脚本使用该标志格式，但 bit2=0，发送未压缩数据；不需要实现压缩也能使用支持 RLE 的设备。旧协议参考网页：黑平面低半字节 F，红平面 0，续块高半字节 F。

应用层数据上限 244 字节，图片每块最多 242 字节，同时受本机 MTU 限制。每次写入都等待 GATT 响应，任何异常中断流程。仅在所有数据写入成功后刷新。

已有实机验证：黑/红平面各 62 块、传输约 11.6 秒，刷新指令获确认。GATT 确认表示设备接收指令，不代表实体画面质量或刷新完成。上传脚本断开连接前预留 25 秒。

源码入口：`html/js/main.js`（通信）、`html/js/dithering.js`（像素）、`EPD/EPD_service.c`（指令）、`EPD/EPD_config.h`（字段）、`EPD/UC81xx.c`（驱动）。
